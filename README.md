# Wireshark Network Traffic Analysis

A practical lab exploring how DNS, TCP and HTTP work together when requesting a webpage.

## Objective

Capture traffic generated by my Kali Linux VM, identify the main stages of a web request, and explain the findings using packet evidence.

## Tools

- Kali Linux VM
- Wireshark
- nslookup
- curl

## Method

1. Started capturing traffic on the eth interface.
2. Ran `nslookup example.com` to generate DNS traffic.
3. Requested a webpage using:
   `curl --http1.1 --noproxy '*' http://example.com/ -o /dev/null`
4. Used Wireshark display filters to inspect the results.

## Display Filters

| Filter | Purpose |
|---|---|
| `dns` | Inspect DNS queries and responses |
| `http.request` | Find HTTP requests |
| `tcp.stream eq 0` | Inspect the TCP connection used in this capture |

The TCP stream number may differ in another capture.

## Findings

### DNS Resolution

The capture showed A queries for IPv4 addresses and AAAA queries for IPv6 addresses.

One returned IPv4 address matched the destination used by the subsequent HTTP connection.

Repeated DNS queries were also visible before a response arrived from another resolver. Further investigation would be needed to establish why.

### TCP Connection

Packets 26–28 showed the three-way handshake:

- SYN: the client requested a connection.
- SYN-ACK: the server responded.
- ACK: the client confirmed the connection.

The HTTP request followed after the connection was established.

### HTTP Request and Response

Packet 29 contained `GET / HTTP/1.1`.

The request headers identified `example.com` as the host and curl as the client. Packet 31 showed an `HTTP/1.1 200 OK` response.

### Connection Closure

Packets 33–36 showed FIN and ACK packets closing the TCP connection.

## Security Observation

The HTTP request headers were readable in the capture because this connection used unencrypted HTTP.

This demonstrates why sensitive information should be protected using HTTPS.

## What I Learned

- How DNS resolves a domain name into IP addresses.
- How the TCP handshake establishes a connection.
- How to inspect HTTP request headers and response codes.
- How to follow a TCP stream in Wireshark.
- How to connect evidence across different protocols.
